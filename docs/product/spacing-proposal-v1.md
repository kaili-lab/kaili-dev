# T2.4b · 间距方案 v1（历史提案，未采用原样 v1）

已由 [spacing-proposal-v2.md](spacing-proposal-v2.md)（D-139）取代作为实施依据：Kai Li 批准整档保留 18px 的修正版。以下保留 v1 当时的提案与算术，不作为待审批问题或现行规范。

当时状态（历史原文）：提案，不是已生效规范。依据 `spacing-inventory.md`（T2.4a），覆盖 71 个「分类 + 原值」条目、407 次出现。布局间距 49 个值 / 358 次；行高、字距 22 个值 / 49 次另列。**当时不修改 token、组件、design.md 或 HTML 参照稿；未拍板不开始 T2.5 / T2.6。**当前批准与依赖以 v2、D-139 及进度表为准。

## 1. 你要决定什么

把目前分散的正数 px 布局间距收敛到下面的数值集合，保留长文按字号变化的 em 间距、装饰定位与排版值。不选“所有数字都按 4px 取整”：1px 的边缘定位和 1.15em 的段落间距不是同一类东西。

| 选择 | 做什么 | 可确定的后果 |
|---|---|---|
| 采用 v1 | 按 §3 的唯一映射执行；30 种正数 px 收敛为 20 种（19 种原值不变，90→88 产生 1 个新值），另有 0 | 11 个旧值、57 次出现改变，单值最多 2px，但会叠加：不新增换行时四行“此刻”桌面约高 12px、手机约高 10px；目录层级缩进差 14→12px。64px 栏距、40 / 28 / 20px 页边距不变 |
| 保留参照稿原值 | 不采用本提案，布局数值仍按清单原样 | 没有本提案的取整差异，但 14 / 15 / 16、18 / 20 / 22、26 / 28 / 30 / 32 / 34 等间距继续并存，需要重做 T2.4b 方案才能推进 |

**我的倾向：采用 v1。前提是允许单值最多 2px 的归并，以及它们叠加后的组件变化和目录 12px 层级差，以减少重复规格。**如果要求逐像素保留参照稿，或不能接受目录层级差缩小，应选保留原值，不要批准后又逐处恢复。本提案未做改后截图，不能声称“看不出区别”；§4 列出按断点计算的局部影响，T2.5 / T3.3 的截图仍须人工确认。

你可以直接答“采用 v1”或“保留原值”；需要改某项时，指明 §3 的旧值和目标值。任何修改先生成新版本并复核，不默认为批准。

## 2. 刻度及范围

**布局刻度（px）：0 / 2 / 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 28 / 32 / 36 / 40 / 44 / 48 / 56 / 60 / 64 / 72 / 88。**

- 2～12px 保留 2px 精度：书架两行之间 2px、作者/元信息 6px、胶囊内边距 8px、备注与正文之间 10px都能保留；不强行统一为 4px 倍数。
- 12～48px 使用 4px 步长；56 / 60 / 64 / 72 保留大区域留白和栏距，90→88。不是要求每个 4px 倍数都登记；只有本提案用到的值列入。
- 0 与 auto 原样：auto 是自动吸收剩余空间或居中，不是可取整的长度。负数 px 和 `-.08em` 都用于边缘对齐或装饰几何，原样保留，不作为普通 gap / padding 刻度。
- 长文与行内代码的 em 间距原样保留，维持跟随各元素字号变化的效果。例如 `1.15em` 是“该元素字号 × 1.15”，不能一律用 18px 代替；所有保留值也在 §3 唯一映射中，不是漏项。
- 行高、字距归排版，§3.3 全部不变；已有的规范缺口（如手机首屏行高 1.22）仍在实施计划「需要先定的事」，本提案不借保留原值把它补定。
- 只处理清单列出的 margin / padding / gap / inset / 四方向偏移及 scroll-margin / scroll-padding。字体字号、宽高、圆角、边框、outline-offset、transform、图片裁切均不在范围。尤其印章宽 34px 不因“间距 34→32”变为 32px，正文最大 41rem、顶栏高 76px 和 OG 1200×630不变。
- 本表用 px 作为比较与迁移口径，不另引入 rem 换算或全局 `--space-*`。组件内部复用刻度值；若用 Tailwind 标准 utility，须确认实际计算值等于本表目标。实现方式留到 T2.5，不能把默认 Tailwind 全部间距当成本方案自动批准。
