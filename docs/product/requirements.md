## 0. 为什么做（动机，用于后续取舍时对照）

Kai Li 自述的三个动机，之后所有功能都应能回答「服务于哪一条」：

1. **把想法写成文章。** 一方面展示个人能力与思想，另一方面写作本身逼迫思考。现状：推特上收藏了很多好东西，但「只是收藏了」，没进脑子。
2. **在快速变化中提炼不变的东西。** 对变化速度感到焦虑；承认视角、技能要跟着变，但也相信有些东西很少变。希望通过写下来把这些「不变量」真正变成自己思想的一部分。
3. **让日常浏览到的观点想得更深。** 否则只是浅层记忆，很快遗失。

**[定] D-010 / D-041 / D-042** 由此确定的输入到输出循环：

```
输入（两种方式）
  ├─ Chrome 插件保存外部资源，并顺手记录当时的想法
  └─ 独立记录没有外部来源的 Idea
        │
        │  之后决定深入思考
        ▼
创建文章草稿（可从 Idea 或 Resource 发起，发起时预先加入对应参考资料）
  → 文章可以关联零到多条 Resource 和零到多条 Idea，编辑器中合并显示参考资料列表
        │
        ▼
发布（站内发布；X 发推为首期之外的后置辅助）
```

资源和 Idea 都是私人输入；文章是独立输出。资源或 Idea 被修改、删除时，文章正文和已发布内容不受影响。

旁路：**脉络**（§5）是一条独立的手工记录线，记业界重点事件，不依赖上面的循环。

## 2. 博客 · 输出侧（文章）— 当前焦点

### 2.1 内容存放与架构 [部分已定，其他基础设施仍待定]

**[定] D-014** 资源库优先级高，博客设计必须从第一天为它留位置。由此推论：

- 需要后端 + 数据库 + 单用户后台，这不是「后话」而是第一版就要有的基础。
- 文章与资源应放在同一个数据库；文章与资源通过可选的多对多关联建立关系，支持一篇文章关联零到多条资源、一条资源关联多篇文章。
- 这替代 D-011 原先“文章源自单条资源”的关系模型。

D-041 已确定文章与资源的多对多关系及资源删除行为。编辑器方向见 D-045；文章图片存储与访问见 D-046 / D-048；网页快照、附件及其他对象的存储与访问策略仍待确定（见 §7）。

### 2.2 文章模型

- **[定] D-012** 只有一种文章类型。
- **[定] D-016** `category`（单选）+ `tags[]`（多选）。
- **[定] D-026 / D-030** 文章支持 zh / en 两种版本，但英文可选，不要求每篇文章都有两个版本。

最小字段（[议]，结构上）：

```text
Post
  slug
  category          单选，必填（D-118）；分类有 nameZh / nameEn / slug
  tags[]            多选；标签有 nameZh / nameEn / slug（D-118）
  pinned            bool          → v1 不设置（D-104）
  resourceLinks[]   关联的资源（零到多条）
  ideaLinks[]       关联的 Idea（零到多条）
  versions: { zh?: PostVersion, en?: PostVersion }

PostVersion
  title
  summary           列表用一句话
  body              Markdown
  status            draft | published
  publishedAt? / updatedAt
```

- **[定] D-026** zh / en 是两个独立的内容版本，可以分别保存、分别发布；一篇文章可以只有一个已发布语言版本。某语言版本未发布时，该语言的首页、列表和文章页不显示它。supersedes D-018 关于“两个版本齐全后才能发布”的约束。
- **[定] D-030** 英文可以由 Kai Li 自己写，也可以基于中文生成 AI 英文草稿；人工检查、修改后再独立发布。AI 不自动发布，中文发布不等待英文。

- **[定] D-102** 分类集合现在不定，写文章时在后台按需创建。
- **[定] D-118** 分类必填；编辑器分类选择旁提供「新建分类」弹窗，创建后自动选中。分类和标签都有中文名、英文名和 slug，英文页面显示英文名。

- **[定] D-123** 分类必填在保存时检查，草稿也必须先选分类。

### 2.2.1 URL 与分享链接 [定 · D-027]

背景：Kai Li 接下来找海外远程工作，读者既有外国人也有海外华人，分享文章时不确定先展示哪种语言。

建议方案：

- 正式页面带语言前缀：`/en/writing/<slug>`、`/zh/writing/<slug>`，互设 `hreflang`，各自可被搜索引擎独立索引。
- **[定] D-027** 访问者首次访问时按浏览器语言自动选择应用语言；顶栏在 light/dark 模式旁提供语言切换按钮，手动选择覆盖自动选择并记住选择。语言切换作用于当前页面，包括当前文章的语言版本。
- 另提供一个**语言中立的分享链接** `/writing/<slug>`（无前缀）：服务端按 `effective` 语言选择一个已发布的语言版本；`effective` 优先使用已保存的手动语言偏好，没有手动偏好时才使用 `Accept-Language`。如果首选语言未发布，回退到另一已发布语言；两种语言都未发布时返回 404。
- **[定] D-036** 全站语言按钮始终可用：当前文章有已发布的目标语言版本时进入对应文章页；否则进入目标语言文章列表，仅在本次切换后提示一次该文章暂无目标语言版本。普通进入列表页不显示提示。直接访问未发布语言的文章 URL 仍返回 404。

- **[定 · D-165]** 公开站指向页面路由的站内链接使用客户端跳转，筛选、清除筛选、顶栏导航、首页区块、文章页、Projects、书架和 404 返回首页不因点击整页刷新；Router `Link` 仍输出带 `href` 的 `<a>`，关闭 JavaScript 时链接仍可用。语言切换保留 D-036 的文章存在 / 不存在分支、一次性提示、D-142 的手动偏好与回退规则；`/` 与无前缀 `/writing/<slug>`（服务端按语言偏好重定向）、外链、正文 Markdown 链接、目录锚点和 `/og`、`/sitemap.xml` 等非页面资源仍是浏览器原生跳转；切换语言后的一次性提示在离开该地址后不再出现。

- **[定] D-142**：`Accept-Language` 为空或无法识别中文、英文时，根路径默认进入 `/zh`；无前缀中立分享链接遵守已保存的手动语言偏好，手动偏好优先于浏览器语言，没有手动偏好时才按 `Accept-Language` 选择。中立链接目标语言未发布时回退到另一已发布语言，两种都未发布时返回 404。
- **[定] D-143** 无语言偏好的爬虫与普通访问使用同一 `effective` 规则并跟随 302；OG 使用最终正式页面的已发布语言标题与摘要，不另设英文优先规则。两种版本都未发布时不生成公开文章卡片。

- **[定 · D-181]** 文章使用单一、语言无关的 slug；中文文章也优先使用面向国际读者的英文语义 slug，不使用中文拼音作为默认方案。slug 可在首次发布前自动生成并由 Kai Li 修改；AI 只能提供候选，不能阻塞保存或发布，也不能覆盖用户已填写的值。任一语言首次发布后 slug 锁定；标题或另一语言内容变化不得自动修改已公开 URL。 `→ v2（AI 候选部分，D-182）`；v1 中 slug 只由 Kai Li 手填，不做非 AI 自动生成（D-183），其余规则不变。

补充说明：X 的自动翻译只翻推文正文，不翻链接目标页面，所以页面自身的语言路由是必要的。

### 2.2.2 首页与列表的语言

- 首页根路径 `/` 按 `effective` 语言 302 到 `/en` 或 `/zh`；`effective` 优先使用已保存手动偏好，没有时按 `Accept-Language`，空或无法识别中文/英文时回退 `/zh`。语言前缀首页和列表只显示该语言已发布版本，英文环境不回退展示只有中文的文章。OG 爬虫按 D-143 使用最终页面语言。

### 2.3 列表与首页

- **[定]** 首页显示最近 5 篇；每条 = 日期 · 标题 · 一句摘要（去掉语言徽标）。
- **[定] D-037** 统一文章列表通过 URL query string 按分类和标签筛选；首期一次选择一个分类、一个标签，同时选择时取交集，只展示当前语言已发布内容。不创建独立公开分类页或标签页。
- **[定] D-037** 后台提供一个分类与标签管理页面，使用两个 tab 分别管理；文章分类单选、标签多选，沿用 D-016。具体界面另行讨论。
- **[定] D-053** 文章和资源共用后台维护的一份标签列表，各自多选；同名标签无需分别创建，修改某条内容的标签选择不影响其他内容。
- **[定] D-050** 第一版文章列表按发布时间倒序，显示日期、标题和摘要；沿用 D-037 的分类/标签筛选。首期不做分页和按年份分组，置顶沿用已有常规字段，不新增复杂排序规则。 `→ v1 不做置顶，列表按发布时间倒序（D-104）`

### 2.4 文章页 [部分已定]

- **[定] D-117** 正文使用衬线体（中文思源宋体 400，英文 Source Serif 4）；长文排版规则见 `design.md`。代码块高亮；图片。
- **[定] D-049** 第一版文章页包含 TOC、阅读时长、上一篇和下一篇；上一篇/下一篇只在存在对应文章时显示。
- **[定] D-078** 公开文章不显示参考资料（Resource / Idea）。
- **[定] D-041** 文章关联的资源被删除时，只删除关联记录；文章正文和已发布内容不变，不保留删除后的来源快照。
- **[定] D-017** 不做评论区；文章页的 X 讨论链接不进入首期，按 D-031 后置。

### 2.5 发布流程 [核心规则已定，后置辅助议题仍待定]

- 后台发布某个语言版本时，只校验该版本自己的必填字段；另一语言版本可以不存在或仍为草稿。
- **[定] D-021** 发推不用 AI 写内容。P2 可做的辅助只有：发布成功后给一个「去 X 发推」按钮，打开 X 编辑框并预填分享链接（§2.2.1 的中立链接），正文 Kai Li 手写；OG 卡片负责视觉吸引。
- **[定] D-031** `tweetUrl` 与文章页「在 X 上讨论 →」链接不进入首期，不影响文章发布；未来是否加入文章表单另行评估。
- **[定] D-034** 保存只保存当前语言版本的编辑内容，不改变公开页面；发布才把该语言版本更新到公开页面。编辑已发布版本时，保存后的内容仍是待发布编辑内容；再次发布后才公开。只保留当前草稿和当前公开内容，不做历史版本、审核流或回滚界面。
- **[定] D-038** 文章编辑采用手动保存，不做首期自动保存；保存只写入当前语言版本的编辑内容，不改变公开页面，发布才更新线上。页面离开前可提示存在未保存修改，但不引入服务端自动保存。
- **[定] D-039** 草稿只在编辑器内预览，不生成独立草稿预览链接；未发布内容不对公开页面、搜索引擎或未登录用户开放。
- **[定] D-040** 首期只支持手动发布，不做定时发布；不增加 `scheduledAt`、定时状态或 Cron 发布任务。

- **[定 · D-176]** 文章的中文和英文公开版本独立撤下。当前语言有公开版本时可以撤下，撤下保留草稿和历史公开快照但不再出现在公开文章页、无前缀中立链接、网站地图或匿名图片访问中；再次发布恢复公开并保留首次发布时间。只有所有语言都没有公开版本时才允许永久删除文章；删除同时清除双语草稿 / 公开快照、Idea 关系和媒体引用，媒体对象按 D-047 的七天清理处理。不做回收站、历史版本或自动 redirect。

- **[定 · D-177]** 撤下语言的历史公开图片保留为私有 `withdrawn` 引用，重新发布时恢复；永久删除文章后引用才随文章删除并进入七天清理。撤下快照里的旧分类 / 标签不再作为公开引用，也不阻止后续删除或改名。

- **[定 · D-178]** 撤下不承诺立即清除已被浏览器或 CDN 缓存的图片字节；v1 只保证新的服务端请求不再授权匿名读取，不做媒体 URL 轮换或缓存清除服务。

### 2.6 站内编辑器 [方向已定，具体实现按 D-045 验证]

文章编辑采用轻量 Markdown 方案，不使用块编辑器或复杂协作编辑器；具体库、布局和快捷键按实现验证调整。块编辑器通常使用私有 JSON，导出 Markdown 可能有损，因此不纳入首期。

- **[定] D-020** 不做中英并排编辑；编辑区上方使用 `zh` / `en` 两个 tab 切换。两个语言版本共享 `slug`、分类、标签和置顶等元数据（v1 无置顶，D-104）。
- **[定] D-045** 第一版采用轻量、成熟的 Markdown 编辑方案，提供编辑、预览、手动保存、手动发布、中文/英文 tab 和基本 Markdown 渲染；具体编辑器库、布局和快捷键按实现建议落地，不引入块编辑器或复杂协作能力。
- **[定] D-071** 文章和 Idea 共用同一个 Markdown 编辑器组件，复用 Markdown 输入、预览、解析和渲染能力。文章使用语言、保存和发布配置；Idea 使用简单输入配置，不建立第二套 Idea 编辑器。
- **[定] D-046 / D-048** 图片粘贴或选择后上传到 Cloudflare R2。R2 对象保持私有；登录后台可以读取草稿和临时图片，匿名访问只允许通过公开应用读取已发布版本引用的图片。图片引用按 `zh` 草稿、`zh` 已发布、`en` 草稿、`en` 已发布四个槽位独立登记，保存或发布只更新当前语言对应的槽位。
